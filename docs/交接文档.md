## 3. 环境与常用命令速查

全部工具链在项目 `.tools/` 内（用户要求：下载不落项目外）。

```bash
# 服务器（本机 8787；新会话需重启）
cd /d/zcode-remote/server && npm install && node src/index.js   # 后台跑

# App 构建（JAVA_HOME 必须设，GRADLE_USER_HOME 保持项目内）
cd /d/zcode-remote/android
JAVA_HOME=D:/JAVA GRADLE_USER_HOME=D:/zcode-remote/.tools/gradle-home \
  /d/zcode-remote/.tools/gradle/gradle-8.10.2/bin/gradle :app:assembleDebug

# 模拟器（AVD medium_phone 已建，Hyper-V 可用）
/d/zcode-remote/.tools/android-sdk/emulator/emulator.exe -avd medium_phone -no-boot-anim &

# adb（注意 MSYS 路径转换！）
export MSYS_NO_PATHCONV=1
A=/d/zcode-remote/.tools/android-sdk/platform-tools/adb.exe
$A install -r /d/zcode-remote/android/app/build/outputs/apk/debug/app-debug.apk
$A shell am start -n com.mstars.zcoderemote/.MainActivity
$A exec-out screencap -p > shot.png
```

**踩过的坑（务必记住）**：
1. Git Bash 会把 `/sdcard` `/list` 等转成本地路径 → adb/cmd 命令一律 `MSYS_NO_PATHCONV=1`
2. curl `-d '中文'` 会被 GBK 编码毁掉 → 测试用 node fetch（见 test/smoke.mjs）或 `--data-binary @file`
3. 模拟器截图 900×2000，真机 1080×2400 → adb input tap 坐标要 ×1.2
4. App 预置配置：root 权限写 `/data/data/com.mstars.zcoderemote/shared_prefs/zcode-remote.xml`（`adb root` 可用，非 Play 镜像）
5. App 发送中文任务无问题（UTF-8），但 `adb input text` 只能 ASCII（空格用 `%s`）
6. MCP android-emulator 插件进程拿不到新 SDK 环境变量（启动时注入的），直接用 bash+adb 代替

## 5. Phase 2 协议探测成果（最值钱的部分）

**app-server 是官方完整控制协议**（Desktop 前后端同款）。探测脚本：`.tools/probe4.mjs`（最新可用），日志：`.tools/appserver-probe4.log`。

### 5.1 启动方式

```bash
ELECTRON_RUN_AS_NODE=1 "D:/zcode/ZCode.exe" "D:/zcode/resources/glm/zcode.cjs" app-server --stdio
```
- ⚠️ 必须用 Electron 当 node（系统 node 22 会报 `SQLite migration transaction ownership mismatch`）
- ⚠️ 与正在运行的 Desktop 并存 OK（probe 实测通过，能列出 Desktop 的实时会话）
- ndjson 帧格式；封包是 `{id, method, params}`，**不是标准 JSON-RPC**（带 `jsonrpc` 字段会被拒）；响应 `{id, result}` 或 `{id, error:{code,data,message}}`

### 5.2 已验证的报文

| 方法 | 参数 | 响应/行为 |
|---|---|---|
| `session/list` | `{}` | ✅ 返回全部会话（含 Desktop 正开着的），字段：sessionId/title/mode/status/sessionKind/workspace/createdAt |
| `session/create` | `{workspace:{workspacePath:"D:/x", workspaceKey:"D:/x"}}` | ✅ 返回 `{messages, projection:{contextWindow,mode,status,totalTokenCount,turnCount,...}, protocol:{name:"ZCode Protocol",version:1}, session:{sessionId,...}, settings}`（首次响应较慢 ~10s） |
| `session/send` | `{sessionId, content:"..."}` | ✅ `{accepted:true, sessionId, stateRevision}`（注意字段是 **content** 不是 text） |
| `session/setModel` / `setThoughtLevel` / `setMode` / `stop` / `messages` / `usage` | 未逐一探测 | 方法名已从 bundle 确认存在 |

**服务器反向请求（关键！）**：会话创建后服务器会发 `{id:"server-N", method:"session/requestRuntimePreferences", params:{...}}` 给客户端，**必须应答** `{id:"server-N", result:{nativeSearchEnhancementsEnabled:false}}`，否则后续流程报 ZodError。其他反向请求可能也有 schema 要求，按错误信息迭代即可（zod 报错会精确告诉缺哪个字段——这是最快的探测方式）。

**观察到的事件（服务器→客户端通知）**：`session/lifecycle/changed`（starting/…）、`state.updated`（含 projection 变化，**流式渲染的数据源，payload 细节待深挖**）、`process/mcpTelemetry`、`computer-use/operation-event`、`v4/telemetry/event`。

### 5.3 Phase 2 探测进度（2026-11-05 更新：95% 打通，仅剩模型注册表）

**已实测打通**（probe5/7/19，脚本在 `.tools/`，日志 `appserver-probe*.log`）：

| 方法 | 参数 | 结果 |
|---|---|---|
| `session/list` | `{}` | ✅ 50 个会话全列出（含 Desktop 实时会话） |
| `session/create` | `{workspace:{workspacePath,workspaceKey}}` | ✅ 返回 session/projection/settings 全量对象 |
| `session/send` | `{sessionId, content}` | ✅ `{accepted:true,stateRevision}`（字段是 **content** 不是 text） |
| `session/messages` | `{sessionId}` | ✅ 完整消息数组（info.role/semantics.kind + parts[{type:'text',text}]） |
| `session/stop` | `{sessionId}` | ✅ |
| `session/setMode` | mode ∈ plan/build/edit/yolo/guarded/auto | schema 确认 |
| `session/setModel` | `{sessionId, model:{providerId,modelId}}` | 协议对，**卡在注册表空**（见下） |
| `session/setThoughtLevel` | `{sessionId, thoughtLevel}` | 待给合法值 |
| `provider/updateAccountConfig` | `{revision, basedOnZCodeBuiltinRevision, providers:{id:{builtinModelIds, access:{type:'zhipu-account',entitled}}}, states:{id:{availability:'available',entitled:true,current:true}}}` | ✅ `{providerCount:1,status:'received'}` 但 **setModel 仍报注册表无模型** |
| `provider/refreshRegistry` | `{reason}` | ✅ refreshed:true |

**事件流**：`state.updated`（patch+reason，如 `{patch:{status:'running'},reason:'prompt_started'}`；失败 reason=prompt_failed 且 patch 带 `model.available=[]`）、`session/lifecycle/changed`（starting→ready）、`process/mcpTelemetry`。**服务器反向请求必须应答**：`session/requestRuntimePreferences` → `{result:{nativeSearchEnhancementsEnabled:false}}`（schema=Uon，严格模式，不含模型字段）；`interaction/requestOfficialMcpAuthHeaders` → 同样格式应答即可继续。

**唯一剩余堵点：独立 app-server 的模型注册表为空**（resume Desktop 老会话也一样 → prompt_failed/model.available=[]）。已排除：`--surface desktop`、环境变量个人配置文件（形状纠正后仍未生效）、updateAccountConfig+states、resume。Desktop 自身凭据不落盘（`~/.zcode/v2/provider_config.json` 是空壳；凭据由 Desktop 进程持有、运行时经 interaction 应答）。

**候选解法（按推荐序）**：
1. **API Key 方案**：写 personal provider 配置文件（`ZCODE_BUILTIN_PROVIDER_CONFIG_FILE` + `ZCODE_PERSONAL_PROVIDER_CONFIG_FILE` **必须成对**传给 app-server）。文件 schema 已全部挖出（见下"关键 schema"），还差最后一个：manualProviderModelRules 的 `config:v3` 内部字段（grep bundle `v3=m.object` / `a7=m.object` 继续）。需要用户到 bigmodel.cn 创建 API key（注意：独立计费，与 coding plan 订阅分开）。
2. **MCP 会话内模式兜底**（M2 已验证可用）：桥接作为插件 MCP 跑在 Desktop 会话里，天然有模型。App v2 UI 先接此模式（单会话遥控），API key 到位后切独立模式（多会话全功能）。
3. 继续逆向 Desktop↔app-server 凭据交互（interaction/* 消息族）——成本高，不建议。

**关键 schema 速查**（bundle 内位置均已定位）：
- 账号条目 Xis：`{builtinModelIds, access:{type,entitled}}`（zcode.cjs 84 行附近 `Xis=l7.pick...`）
- 个人配置文件：`{schemaVersion, config:{providerConfigRules:{providerRules[His]}, modelConfigRules:{providerModelRules[rOe], manualProviderModelRules[ren]}, providerOrder, defaultModelSelection}}`
- His=oen+config：`{providerId, config:{access?, api?, group?}}`（个人规则**不能带 builtinModelIds**；`account:` 前缀 providerId 不能设 access）
- 模型规则：rOe=`{providerId, modelId, config:c7}`；ren=+`config:v3`；c7/v3 的字段还要挖
- states：`{providerId:{availability:'available'|'pending'|'unavailable'|'unknown', entitled:bool, current?, connectionKey?, effectiveAt?}}`
- 内置模板：`/d/zcode/resources/config/provider/zcode-builtin.json`（模板 bigmodel-api：anthropic-messages + open.bigmodel.cn + GLM-5.3/GLM-5.3-Flash）

### 5.4 无头 CLI 附带发现（备用路径）

`zcode.cjs -p "..."`（无头单发）：同样必须 ELECTRON_RUN_AS_NODE；`--model` 参数传 `GLM-5.3-Flash` 会打印 help（未接上），报 `Select a model before sending a message`。根因与 5.3 相同（无模型注册表）。**app-server + API key 解决后此路自动通。**

## 7. 已知风险

- Stop/PermissionRequest hook 输出 schema 未在真实客户端验证（写法来自 Claude Code 兼容格式）
- 远程批准超时默认拒绝（5 分钟）；`--mode yolo` 语义要在 Phase 2 里映射到 `session/setMode`
- 公网部署必须 HTTPS，否则 token 与任务明文裸奔
- 电脑睡眠 = 断网失联（提醒用户电源设「从不睡眠」）
